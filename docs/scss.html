Secure Coding Policy

About:

An important aspect of computer science is being able to implement best practices into our work. A system must be designed for security from the start. Retroactively applying security can leave gaps in the armor. This page serves as a reminder to why and how programs should be protected.

Security Principles

Validate Input Data

All types of input data must be checked and verified. Data that is entered which does not match the intended purpose can result in errors and unintended behavior. These results are exploitable.

Heed Compiler Warnings

Compilers are powerful tools that can provide insight into the behavior of a program should there be an issue. In-built warnings can assist one in developing safe and secure code. Be sure to check that code is not flagging any errors or warnings before compilation.

Architect and Design for Security Policies

From the start, it is imperative that all staff plan their actions to utilize best security practices. A secure foundation is necessary to build and maintain a secure project.

Keep It Simple

One module; one purpose. Keep the code modular. This ensures readability and reduces potential errors from excessive bulk.

Default Deny

The default behavior of any program should be to deny. Only through verification can a user continue. Rejecting unilaterally can protect against unintended behaviors.

Adhere to the Principle of Least Privilege

In terms of access, privileges should be kept at a minimum. If a user does not need the privilege for their tasks, then remove said privilege. Otherwise, an individual has elevated access where they should not.

Sanitize Data Sent to Other Systems

By properly maintaining data that is to be sent out of a system, one can ensure that information is being correctly handled. This will protect the data’s integrity and confidentiality in transit. A clean transaction.

Practice Defense in Depth

One defensive tactic is not enough. There are many attack surfaces that could be exploited. Utilize a layered defense of many techniques that fit the circumstance. If an attacker manages to get past one, then their progress will only be met with another defensive line.

Use Effective Quality Assurance Techniques

There are many assist tools and practices that can ensure quality throughout projects. By utilizing powerful tools of automation and test cases, one can definitively prove that their work is operating as intended.

Adopt a Secure Coding Standard

Security and bugs in code have been well documented. Many exploits have been met and resolved as programming has matured. Incidents tend to be the result of the lack of a Secure Coding Standard.

Coding Standards

Coding standards are important reference materials to guide you in the development process. Chances are a security vulnerability that one is dealing with has already been dealt before. There are ways to detect common vulnerabilities and anti-patterns in your program with static analysis tools. Depending on the programming language, the coding standard will have its quirks to match the behavior of the language. There may also be a coninciding style guide to one maintain a consistent format with other developers.

Encryption Policy

Encryption at Rest

Data at rest means when data is sitting in storage. Encrypting this data in storage will prevent any threat actors from being able to actually read the data. In the event of a breach, even if this data is acquired, it should still be safe as the hacker lacks the key to decrypt the information hidden.

Encryption in Flight

Data in flight means when the data is being sent to and, or from two endpoints. Encrypting data in this state prevents threat actors who may have intercepted this data from being able to read the data. Without the key to decrypt, the data remains protected.

Encryption in Use

Data in use means when a process/system is utilizing data. Active data, even if it changes, is considered to be the most vulnerable. It is integral to security to encrypt data throughout the process as threat actors may exploit this vulnerability.

Triple-A Framework

Authentication

Authentication is how we identify a user is truly who they are logging in as. Commonly, two-factor-authentication is implemented upon logins and account creations. By utilizing what a user knows (login credentials) and what a user has (i.e. access to an email), we can tighten the authentication process for better security.

Authorization

Even if a user logs into a user, they cannot do anything without being authorized to do so. Authorization is the permitting of access to a user account. It is important to follow strict access-control to prevent a user from accessing objects that they should not be around. This will limit the impact of a compromised account as they have reduced authorization to a system.

Accounting

Accounting is logging all instances of user actions in a system. By documenting each action, we can trace the steps of all users to the system. We can read the time they logged in, what files were accessed, and what operations they took to do so. Anomalies in a user’s actions may indicate that a breach has occurred due to erroneous or scripted behavior. Accounting allows us to vet the user for further confirmation.
